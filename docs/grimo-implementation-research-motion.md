# Grimo のタッチ演技制作調査

調査日: 2026-09-07 JST  
対象: `docs/grimo-final-spec.md` の承認済み5体（キャロル、ピノ、ジル、シュシュ、ムゥ）  
目的: 既存の原画を固定したまま、0円・新規依存なしで、入力への応答、中断可能な演技、反復感の抑制、無音でも成立する世界を制作するための技法を決める。

## 先に決める制作方式

最初の実装は、既存のブラウザで使える Pointer Events、CSS、Web Animations API（WAAPI）と、許諾確認済みの透明画像レイヤーだけで作る。新しいSDK、実行時の画像生成、外部API、効果音・音楽素材の追加、Live2D/Rive/Adobe製品の導入は前提にしない。これなら資料を読む費用も実装費も0円で、現在のWeb構成から検証できる。

制作対象は5体を厳守する。1体を先に合格させる場合も、キャロルを試作対象にするだけで、別キャラクターを追加しない。提供画像の顔、シルエット、比率、色、装飾配置は基準画像として固定し、原画にない変形で品質を補わない。

演技は次の層に分ける。各層が同じCSSプロパティを奪い合わないよう、担当する部位とプロパティを制作表に固定する。

| 層 | 担当 | 入力時の扱い |
|---|---|---|
| 基本 | 呼吸、まばたき、視線、微細な姿勢 | 常時または待機中。入力で停止させない |
| 接触 | 接触部位の局所反応、姿勢の意図 | `pointerdown` 直後に受け止め、現在姿勢から遷移 |
| 余韻 | 毛、尾、翼、耳、手などの遅れと戻り | 主動作の後に少し遅れて追従。新入力で中断可能 |
| 環境 | 雲、泡、水輪、葉、花びら、光 | キャラクターの顔と接点を隠さない。無音でも動く |

原画を分ける工程では、原本を読み取り専用の基準として保存し、頭・胴・左右の目とまぶた・口・耳・手足・毛・尾・翼・装飾を必要な範囲だけ透明レイヤーへ分ける。隠れていた輪郭は補修前後を基準画像と照合する。瞬きは黒い楕円を上貼りせず、原画に合う閉じ目の形を作る。これはLive2DのPSD制作資料から借りる考え方であり、Live2D形式やSDKを使う判断ではない。

## 入力から返事まで

W3C Pointer Events は、マウス・ペン・タッチを共通の `pointerdown`、`pointermove`、`pointerup`、`pointercancel` として扱える。`pointerdown` で対象に `setPointerCapture(pointerId)` を設定すると、指が対象の外へ少し出ても同じ対象で移動を追跡できる。`pointerup` と `pointercancel` では必ず解除し、途中キャンセルを離した状態へ戻す。キャラクター領域だけに `touch-action` を設定し、ページスクロールを必要以上に奪わない。キーボードには別に Enter/Space または同等の「つつく」「押して待つ」操作を用意する。W3C資料もキーボードは Pointer Events の対象外なので明示的な処理が必要としている。

実装手順は次の順にする。

1. `pointerdown` で時刻、開始座標、接触部位、入力種別を保存し、100msを待たずに局所の受け止めを出す。
2. `pointermove` では経過時間、移動距離、速度、方向、接触部位を更新する。高頻度の移動を使う場合だけ `getCoalescedEvents()` を検討し、入力履歴を無制限に保存しない。
3. 接触を短く終えれば「つつく」、接触したまま滑らかに動けば「ゆっくりなでる」、速度が高ければ「速くなでる」、約600ms前後の保持なら「押して待つ」とする。閾値は実機で調整し、圧力は必要条件にしない。
4. `pointerup` は離した時点の余韻へ、`pointercancel`・画面非表示・ページ離脱は安全な待機姿勢へ接続する。入力をアニメーションの完了待ちキューに積まない。
5. マウスの hover は視線追従の補助として使い、スマホで画面外の手の接近を検知できるとは約束しない。

## 中断可能なアニメーション

WAAPI には再生、停止、逆再生、速度変更、終了通知、キャンセルがあり、W3C仕様にはアニメーション効果の合成順と置換、反復の定義がある。新しい反応が来たら、現在の姿勢を開始値にして次の短い遷移を作る。前の長い演技を最後まで再生してから次へ進む方式は採らない。

実装時の遷移規則は以下とする。

- 反応開始時に、該当部位の現在の見た目を読み取り、現在のWAAPIアニメーションを `commitStyles()` 相当で姿勢へ反映してからキャンセルする。新しい効果はその姿勢から開始し、初期位置へスナップさせない。
- 基本層は呼吸・視線を維持し、接触層だけを差し替える。余韻層は主動作と別の短い効果にする。環境層はキャラクターの反応を遮らない範囲で続ける。
- 同じ要素へ反応を連打する場合は、新しい効果を1本だけ持ち、完了待ちの配列を作らない。終了または置換された効果を参照集合から外す。W3C仕様が示すように、イベントごとに forwards-fill のアニメーションを作り続けると、効果が無制限に増える。
- `pointerup` で急に静止画へ戻さず、現在値から小さな戻りと余韻を作る。逆方向の新入力は `reverse()` の再利用または現在値からの短い遷移を選ぶ。
- `prefers-reduced-motion: reduce` では大きな拡縮・パン・揺れを抑え、局所の表情、接点の明るさ、短いフェード、静かな姿勢変化へ置き換える。反応の意味を動きだけに任せない。音OFFでも同じ視覚反応を出す。
- `transform` と `opacity` を中心にし、レイアウトを毎フレーム変更しない。画像サイズや塗りつぶしを動かす必要がある層だけ、実機でPaintとフレーム時間を確認する。

この方式は「入力から最初の見える反応までp95 100ms以内」という企画の仮目標を守るための実装方針である。100msや60fpsは資料が保証する数値ではなく、Grimoの合格基準として実測する。

## 反復感を抑える演技選択

毎回同じアニメーションを先頭から再生すると、タッチが返事ではなく効果音のように見える。反応核を「受け止め」「意図の間」「個性の仕草」「余韻」の4つに分け、各行為に3つ以上の異なる核を用意する。速度だけ、視線位置だけ、音量だけを変えたものは別核に数えない。

選択は単純な乱数にせず、直前の接触部位・移動速度・方向・押していた長さ・直近の反応履歴・穏やかな気分（くつろぐ／遊びたい／興味）を重みにする。直近2〜3個と同じ核を避け、同じ入力を10回続けても同じ演技を続けない。RiveのState Machine資料にある「状態を層に分け、遷移条件と重みを持たせる」という考え方だけを、既存のTypeScriptとWAAPIで小さく再実装する。

待機は複数の自律行動から選ぶ。呼吸、まばたき、視線、環境の微細な動きを同じ周期に揃えず、各ループの位相と次回までの間隔を少しずらす。ただし、ランダムに激しく動かして反復を隠さない。60秒眺めたときに周期の一致が露骨でないことと、5体の人格差が見えることを優先する。

Animation Mentor の spacing 解説が示すように、同じ所要時間でもポーズ間の間隔を変えると加速・減速の印象が変わる。Grimoでは、キャロルのゆっくり沈む動き、ピノの少し遅れて追う手、ジルの胸から翼・尾へ伝わる動き、シュシュの頬寄せの長い余韻、ムゥの一拍置いた返事に、異なる spacing と重なりを作る。

## 5体への適用

| 相棒 | 触れた直後の核 | 余韻と環境 | 音OFF合格の見え方 |
|---|---|---|---|
| キャロル | 接触位置をすぐ受け止め、毛→耳→体の順にゆっくり沈む | 月クッション、雲の端が接触方向へ沈み、毛が遅れて戻る | 目を細め、重みを預ける流れが顔・姿勢だけで読める |
| ピノ | 目が先に追い、手が少し遅れて差し出した方向へ追いつく | 泡を抱える、泡の移動、水輪が接触点から広がる | 追視と遅れた手、泡の抱え込みが一つの返事に見える |
| ジル | 胸を張り、翼の反応から尾へ弾みを渡す | 葉の舟、木の実、花のつぼみ。尾の動きで葉が揺れる | 胸→翼→尾の順序と葉の揺れで元気だが穏やかな性格が読める |
| シュシュ | こちらを一度確かめてから頬を寄せる | 頬寄せの余韻を長めにし、花びらと花束が小さく揺れる | 確認する視線、頬の接近、長い静止で甘えを読める |
| ムゥ | 入力のテンポを受け、一拍置いて会釈または指揮棒を下げる | 尾の拍、花の揺れ、小ピアノとの接点。演奏の正解・失敗は作らない | 一拍の間、頷き、尾の拍で音楽家らしい返事が成立する |

5体すべてで、顔の周囲と指の接点を前景で隠さない。背景を動かすために相棒を小さくしたり、全身を強く拡縮したりしない。原画と専用世界の比率は企画書のまま維持する。

## 原画を固定する制作手順

1. 原本ファイルと利用権を確認し、編集用コピーを作る。原本の色・比率・顔・シルエット・装飾配置を基準画像として固定する。
2. レイヤー表に「部位」「元画像の座標」「前後順」「回転中心」「隠れ部分の補修有無」「担当するアニメーション層」を記録する。1部位を複数の演技で別形状に描き直す場合も、基準画像との比較を残す。
3. 目・まぶた・口など小さな表情部位は専用の閉じ目・表情形を原画の線質で作る。頭・胴の輪郭が崩れる変形や、顔全体の一律な squash/stretch は初版で使わない。
4. CSSの親子要素またはSVG/透明画像のグループで、胴→頭→顔部位→手足・毛・尾・翼→装飾の順を固定する。各部位にアンカーを置き、`transform-origin` のずれを基準画像で修正する。
5. キャロルの「つつく・ゆっくりなでる・押して待つ」を3反応核ずつ制作し、動作の頂点、途中の中断、離した後を原画と並べて確認する。合格した部品構造と選択規則だけを残り4体へ広げる。

Live2DのPSD資料が示す「グループ階層」「原画をガイドとして同梱」「レイヤーをArtMeshへ対応させる」という整理は、レイヤーの漏れを防ぐ参考になる。実際の隠れ部分の補修、レイヤーの合成、輪郭の品質確認はGrimoの素材工程で行う。Live2D EditorやSDKの採用は今回不要なため導入しない。無料版の存在を否定する判断ではなく、既存構成で成立する方式を優先する。

## 具体的な合格条件

以下は企画の完成判定を、制作工程で再現できる測定・試遊に落としたもの。資料の一般論とGrimo固有の暫定値を混同しない。

| 確認 | 合格条件 |
|---|---|
| 入力応答 | 初回・連打・低性能端末で、入力から最初の見える反応までp95 100ms以内。Pointer capture中に対象外へ少し移動してもなでる判定が途切れず、`pointercancel` 後に stuck 状態を残さない |
| 触れ方 | つつく、ゆっくりなでる、速くなでる、押して待つ、離す、何度も触る、道具を近づける、待つを、タッチ・マウス・キーボードの同等経路で再現できる。圧力非対応でも判定できる |
| 中断 | 反応の途中で方向変更、離す、別部位への入力を各10回行い、先行アニメーションの完了を待たずに現在姿勢から遷移する。顔・シルエット・接点に目で分かるスナップ、重複キュー、入力不能を残さない |
| 反復 | 60秒の待機で周期の一致が露骨でない。同種入力10回で同一核を連続再生しない。速度・視線・音量だけでなく、ポーズの順序、間、局所部位の意図が変わる |
| 原画 | 原画との並列比較を静止時・途中・動作頂点で行い、顔、瞳、シルエット、比率、色、装飾配置の崩れがない。まばたきが黒い楕円の上貼りに見えず、隠れ部分に穴や不自然な輪郭の切れがない |
| 個性 | 5体すべてを初回から試せる。各体3行為×3反応核と自律行動を確認し、キャロル／ピノ／ジル／シュシュ／ムゥの違いを説明文なしに見分けられる |
| 無音 | 音をOFFにしても、接触部位、間、視線、姿勢、余韻、環境の反応が成立する。音がないことで入力が失敗したように見えない |
| 動き抑制 | `prefers-reduced-motion` とアプリの動き抑制で大きな移動・拡縮・揺れを抑えつつ、接触への視覚的な返事をすぐ出す。重要な意味をアニメーションだけで伝えない |
| 性能・寿命 | 320/390/1280px、低い横画面、30分放置、復帰、連続入力で確認する。非表示時に自律アニメーションを止め、戻ったときに再開する。console/network/runtimeの異常、新規外部通信、アニメーション参照の増え続けを残さない |

合格しない場合は反応核を増やしてごまかさず、原画のズレ、層の競合、入力判定、遷移の開始値、周期設計のどこが原因かを切り分ける。150反応核は制作目標であり、自然な返事・原画固定・中断可能性を満たさない状態を合格にしない。
